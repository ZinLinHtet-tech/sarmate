# Mate sprite technical specification

This is the asset contract consumed by `components/pet/PetSprite.tsx` and `lib/pet/sprite-assets.ts`.

## File layout

```text
public/pets/sarmate-cat/
├── animation-manifest.json   runtime manifest
├── animation-sheet.png       final runtime atlas
├── contact-sheet.png         every frame, enlarged and labelled
├── preview.html              interactive preview
├── manifest.json             legacy 12×12 single-frame sample
└── spritesheet.png           legacy sample sheet
```

The loader fetches and validates `animation-manifest.json`, confirms the sheet's real pixel dimensions, then renders frames with CSS `background-position`. If anything fails, `PetSprite` falls back to the built-in SVG frames in `public/companion/manifest.json`.

## Manifest schema

```json
{
  "schema": "sarmate-pet-sprites/1",
  "id": "sarmate-cat",
  "displayName": "Mate",
  "sheet": "/pets/sarmate-cat/animation-sheet.png",
  "frameWidth": 32,
  "frameHeight": 32,
  "scale": 2,
  "columns": 74,
  "rows": 1,
  "animations": {
    "greet": { "frames": 6, "fps": 6, "loop": false, "startFrame": 0, "row": 0, "durationMs": 2200 }
  }
}
```

Required fields: `schema`, `id`, `displayName`, public `sheet` path, positive integer `frameWidth`, `frameHeight`, `scale`, `columns`, `rows`. Each animation entry needs `frames` (≥1), `fps` (>0), `loop` (boolean), `startFrame` (≥0), optional `row` and optional `durationMs` (>0).

Enforced constraints: `startFrame + frames <= columns`, `row < rows`, and the PNG must be exactly `columns × frameWidth` by `rows × frameHeight` pixels.

## Frame geometry

- Logical frame: **32×32 pixels**.
- Runtime atlas: **2368×32 pixels** — 74 columns × 1 row.
- Rendered frame: **64×64 CSS px** (`scale = 2`).
- `background-size` is derived as `columns × frameWidth × scale`, so no image is stretched.
- Pixel 0,0 is the top-left of frame 0; frames advance left to right.

## Export and provenance

- Generated by `scripts/build-pet-art.py` with Python 3 and Pillow; no image model, API key or paid service.
- Transparent PNG, RGBA, hard pixel edges, no anti-aliasing, no gradients.
- One image pixel equals one logical pixel. No pre-scaling in the PNG.
- All frames use only the palette in `docs/pet-art-direction.md` plus full transparency.
- The generator validates dimensions, palette, empty frames, clipping/margins and duplicate frames before writing assets.

## Validation checklist

1. `python scripts/build-pet-art.py --check` passes.
2. `npm test` passes, including `tests/pet-sprite.test.ts` (manifest geometry, PNG header dimensions, loader failure, playback and fallback).
3. `contact-sheet.png` shows 74 distinct, labelled frames.
4. Frames keep a 1 px transparent margin; ears, paws and tail are not clipped.
5. Preview at 64×64 CSS px and 4× enlargement on light and dark backgrounds.
6. Browser playback advances `background-position` without flicker or stretching.
7. Renaming the sheet triggers the SVG fallback.

## Runtime notes

- `loadPetSpriteManifest()` caches the validated result per URL; changing assets requires a reload or a new URL.
- Domain animation keys such as `wave`, `jump`, `nod` and `confused` map to sprite keys such as `greet`, `celebrate`, `encourage` and `error`.
- `manifestSrc` on `StudyPet`/`PetSprite` can point at an alternate manifest for A/B art tests.
